* **M2 bugfix round**: Two connection bugs found via on-device SSH debug trace. (1) `_exec` read command output before the remote command finished (dartssh2 `exitCode` is `int?`, null until exit) — token fetch saw empty stdout and falsely reported tower missing; now awaits `waitForExit()` and drains both streams. (2) Device Ed25519 key stored the 32-byte seed; dartssh2 needs the 64-byte expanded secret (`SigningKey.asTypedList`), so key auth aborted with "The list length (32) is invalid". Keygen fixed; broken stored keys auto-regenerate and machines reset to re-bootstrap; keyboard-interactive auth wired (macOS/PAM sshd reject the plain password method); key-auth refusal now prompts for the password to reinstall the key. Verified: keygen proof (PEM loads, 64-byte private blob, 64-byte signature), analyzer 0, tests pass. Authored by claude-code/1.0.
* **M2 HTTP fix**: `TowerConnection.http` called `Socket.write(utf8.encode(head))`; `write` stringifies its argument, so the request line was a bracketed byte list and tower answered 400 with an empty body (shown as "unknown HTTP 400"). Now writes the header string and `add`s the body bytes. The forward `ServerSocket` is also closed with the connection. Verified against a live local tower: `GET /v1/agents` returns 200 with 11 rows through the app's request and parse code; unknown routes return an empty 404 body. The real host is 192.168.1.121 (SSH open, tower API loopback-only). Authored by claude-code/1.0.
* **M2 healthz fix**: `/healthz` requires the bearer token on tower 0.9.0 (401 without it); the earlier claim that it is auth-exempt was wrong. `TowerConnection.health` now takes the token and `SessionController` passes it. Corrected `concepts/tower-api-surface.md`. Authored by claude-code/1.0.
* **M3 done (code)**: Fleet, Inbox, Jobs and Workflows screens render live REST data and refetch on the SSE feed. New: `connection/sse.dart` (incremental HTTP/chunked + SSE parser, unit-tested incl. splits mid UTF-8 and mid-chunk), `TowerConnection.sse` (cancel closes the socket at once; 45 s silence fails the stream), `TowerClient.events`, `api/live_feed.dart` (one feed per ready session, `agent.output` excluded server-side, status dot and reconnect button in the app bar), `features/common/live_resource.dart` (load, debounce 300 ms, pull-to-refresh, retry banner). Bugs found by live probes: task `result` is a JSON object, not a string, so every `GET /v1/tasks` crashed the model; and `async*` streams cancel late on a quiet feed, so the SSE stream is a controller. Verified against an isolated `tower serve` (`TOWER_HOME` temp dir, port 18266): `agents/inbox/tasks/workflows/runs` parse against the live 0.9.0 server (11 agents, 377 tasks, 2 workflows, 8 runs) and a `task.created` event arrives through `TowerClient.events`. Not verified on the phone: it was not connected over adb at the end of the round. Authored by claude-code/1.0.
* **M3 on-device**: Verified on a Pixel 7 against a real host (kobo over Tailscale): Fleet, Jobs and Inbox render live data and the feed dot shows "Live updates on". Found on device: Android aborted the SSH socket (`ECONNABORTED`) about 40 s after connect on one run, which left the session "ready" while requests failed with `Broken pipe`. The session now watches `TowerConnection.closed` and moves to failed ("connection lost; tap it to reconnect"), and the local forward no longer raises unhandled errors when a client closes early. Automatic reconnect stays in M6. Authored by claude-code/1.0.
* **M4 done (code)**: Actions wired as bottom sheets with an inline error strip (a failed call keeps the sheet open; success closes it and shows the server's answer in a snackbar). Fleet: tap an agent to prompt it (shows the returned state, flags `stalled`). Inbox: tap a message to answer (text), approve or deny, or dismiss. Jobs: "Queue job" button (title, description, priority, optional assign) and a per-job sheet with assign, release and cancel (cancel needs two presses). Workflows: tap a workflow to run it; inputs come from the definition and required ones are enforced. Bug found against a live tower: `POST /v1/tasks/{id}/release` requires `{as: <owner_id>}`; the client sent `{reason}` and got 422. Verified against an isolated `tower serve`: unknown agent, workflow and message map to the server's 404, a second cancel maps to 409 `conflict`, create and cancel round-trip. Not exercised end to end: assign, release, prompt and respond success paths and a workflow run, because the isolated server has no agents and no agent-authored messages; request shapes were checked against the server source (`RespondBody`, `PromptBody`, `AssignBody`, `ReleaseBody`). Authored by claude-code/1.0.
* **M5 done**: Detail pages replace the M4 job sheet. Agent detail (Fleet, tap an agent): facts, desired state, a terminal tail (last 60 lines of `GET /v1/agents/{id}/read`, polled every 5 s while open because `agent.output` is excluded from the feed), the agent's jobs, and the Prompt button. Job detail (tap a job anywhere): facts, description, result, the event trail from `GET /v1/tasks/{id}` with agent ids shown as names, and assign / release / cancel (cancel needs two presses). Run detail (Workflows, tap a run): state, input, waiting-for agents, per-step state/agent/outcome/error, live via `workflow.*` events, cancel run with two presses. The Inbox tab icon carries a badge with the pending count, refetched on `message.*` events and when the feed returns. Verified on the Pixel 7 against kobo over the tunnel: agent detail (facts, terminal view, jobs), job detail, and run detail with its steps all render; no Flutter errors in the log. Not verified on a device: the badge (kobo's inbox is empty) and cancel run (no open run). Authored by claude-code/1.0.
